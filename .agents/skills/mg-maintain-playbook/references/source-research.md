# Public-source research for playbook articles

The maintenance workflow owns source discovery and verification. Use this reference when an article makes external factual claims or is reviewed for source support. Give the composition pass a brief with the intended reader/outcome, article type and destination, applicable canonical examples/contracts, adopted MG decisions, and a source packet.

## Find and verify sources

- Prefer current primary sources such as official documentation, standards, or original research. Confirm the source is current for the stated product/version and directly supports the claim.
- Open the direct page without login and read the relevant material. An authenticated session, a login screen, or a successful response that contains only an access gate does not establish public availability.
- Record each relevant source's title, direct public URL, applicable version/date, claim(s) it supports, a concise excerpt or accurate summary, and how/when unauthenticated access was confirmed. Use citations near claims and a concise **Sources** or **References** section in the article.
- A public repository page may be cited only after the same access and relevance check. Relative repository links are for navigation and do not prove public access.
- Technical sources do not prove that MG has adopted a policy. Use only an adopted decision from the assignment or canonical guidance for MG requirements.

## Keep internal material out of reader-facing sources

Internal briefs, task details, admin documents, Trello cards, PR discussions, private Drive/chat content, and ignored work files may clarify scope or record decisions, but must not appear in the article or its source list. Do not include client identifiers, confidential examples, or private operational data. A public task page is still not an appropriate reader source when it exposes internal task details.

If no suitable public source supports a claim, find public evidence, narrow/remove the claim, or leave the draft unready and report a source gap in the maintainer handoff. Do not invent links, change sharing settings, publish material, or silently treat an unverified source as public.
