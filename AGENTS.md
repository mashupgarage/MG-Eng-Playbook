# Repository guidance

## Work

- This is a Markdown engineering playbook; use [mg-maintain-playbook](.agents/skills/mg-maintain-playbook/SKILL.md) as its primary content workflow. Handle tiny mechanical edits directly.
- Stay within assigned scope; report evidence, checks, and gaps.

## Content map

- Canonical areas are `plays/`, `principles/`, `standards/`, `recipes/`, `reference/`, `learning/`, and `start-here/`; follow their indexes and [the migration map](maintenance/migration-map.md).
- Treat legacy paths and indexes as compatibility forwards where the map records moves; when moving content, update the map and local links in the same change, and retain forwards through the first post-migration release per the map.
- Proposed `runbooks/`, `templates/`, and `ai/` folders are absent; create or route content there only when scoped work establishes them.
- These instructions and roadmaps do not establish MG policy.

## Workflow

- For substantive work, follow draft → review → revise → recheck → integrate, whether one agent performs the steps or contributors share them.
- When delegating, assign clear ownership and pass the brief, sources, and artifacts; avoid concurrent edits to the same file.
- Report self-review and independent review accurately. If a task requires independent review and it is unavailable, report that requirement as pending.
